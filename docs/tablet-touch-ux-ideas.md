# 태블릿/모바일 터치 UX 아이디어 (2026-09-09 논의)

태블릿 환경 사용성 질문에서 시작된 논의와 각 항목의 실현 가능성
검토 기록. 구현 착수 전 아이디어 단계 기록이며, 실제 작업은 별도로
TODO.md에 등록 후 진행.

## 논의 배경

3가지 질문에서 출발:

1. 태블릿에서 필기 가능한지
2. 태블릿에서 두 손가락 핀치가 브라우저 페이지 확대가 아니라 PDF
   확대로 동작하는지
3. 태블릿/모바일 디자인 개선 방향(원문·노트 탭 전환 외의 방향)

## 1. PDF 핀치 확대/축소

### 현재 상태

코드 확인 결과 터치/핀치 제스처 핸들러 미존재(`Ctrl/Cmd+스크롤`만
데스크톱 대상으로 처리). `viewport` 메타 태그도 확대를 제한하지 않아,
태블릿에서 두 손가락 핀치는 **브라우저 페이지 전체**를 확대함 — PDF만
확대되는 게 아님.

### 실현 가능성 — 가능, 난이도 낮음

기존 `zoomTo()`(`PdfPane.svelte`) 인프라를 그대로 재사용 가능. 구현
방향:

- PDF 스크롤 영역에 `touch-action: none` 적용.
- 두 손가락 `pointerdown`/`pointermove`로 두 접점 사이 거리 변화를
  측정, 배율로 환산해 기존 `zoomTo()`에 전달.
- 새 컴포넌트 불필요 — 기존 확대 상태 공유 구조에 자연스럽게 편입.

## 2. 필기(ink annotation)

### 실현 가능성 — 가능하지만 하이라이트보다 범위 큼

Zotero가 `ink` annotation 타입을 네이티브로 지원(형식 조사는
[pdf-ink-annotation-research.md](pdf-ink-annotation-research.md) 참고) —
완전히 새로운 설계가 아니라 하이라이트 기능과 같은 패턴의 확장.

추가로 필요한 작업:

- 실시간으로 곡선을 그리는 캔버스 기반 입력 레이어(펜/손가락 겸용).
- 화면 좌표를 PDF 좌표계로 변환하는 로직(하이라이트의 사각형보다
  복잡한 연속 경로 변환).
- Zotero ink 데이터 형식 실측 확인(굵기 필드 위치 등 미확인 사항
  존재 — 별도 문서 참고).
- 펜 압력/굵기 조절 UI.

### 판단

"불가능"이 아니라 "하이라이트보다 확실히 큰 작업 + 데이터 형식 확인
선행 필요"로 정리.

## 3. 추가 태블릿/모바일 디자인 방향

현재는 900px 이하에서 "원문/노트" 탭 전환 방식 하나만 존재. 대안:

- **태블릿 가로모드에서 분할뷰 유지**: 현재 브레이크포인트가 좁은
  폰 화면과 넓은 태블릿을 구분하지 않음. 아이패드 가로 폭(약
  1024px 이상)처럼 여유 있는 화면은 탭 전환 대신 데스크톱과 같은
  분할뷰를 유지하는 편이 자연스러움.
- **노트를 바텀시트로 전환**: 탭 전환 대신 PDF를 계속 보면서 화면
  아래에서 노트를 절반 정도 끌어올리는 방식 — PDF 스크롤 위치를
  유지한 채 메모 확인 가능.
- **하이라이트 팝업 터치 타겟 점검**: 색상 팔레트/삭제 확인 팝업이
  마우스 클릭 기준 크기로 설계됨 — 손가락 터치 기준 크기 재검토
  필요(실측 미실시).
- **스타일러스 정밀 선택 지원**: 손가락보다 정밀한 스타일러스 입력을
  활용한 텍스트/참고문헌 선택 보조.
