# 하이라이트 팝업과 사파리 텍스트 선택 콜아웃 겹침

태블릿에서 단어를 더블탭(더블클릭)하면 사파리 네이티브 텍스트 선택
콜아웃(Copy/Look Up/Share 메뉴)이 형광펜 색상 팔레트 팝업과 겹치는
문제의 조사와 해결 방식 기록.

## 검토한 방향과 배제 사유

| 방향 | 배제 사유 |
| --- | --- |
| `-webkit-touch-callout: none`으로 사파리 콜아웃 제거 | 링크/이미지 롱프레스 메뉴만 막고, 텍스트 선택 콜아웃엔 적용 안 됨(iOS 버전에 따라 아예 안 먹는 사례도 보고됨) |
| `-webkit-user-select: none`으로 선택 자체 차단 | 형광펜 기능에 필요한 네이티브 선택까지 같이 사라짐 — 채택 불가 |
| 필요한 정보를 읽은 뒤 `window.getSelection().removeAllRanges()`로 선택을 즉시 지워 콜아웃 제거 | 사용자 판단: **복사 기능이 필요할 수 있는데 네이티브 콜아웃을 지우면 복사 수단이 사라짐** — 채택 안 함 |

## 채택한 방향 — 우리 팝업 위치를 아래로 우선

사파리 콜아웃은 그대로 유지(복사 기능 보존)하고, 대신 우리 색상
팔레트/삭제 확인 팝업의 기본 방향을 바꿔 겹침을 피함.

**근거**: `PdfViewer.svelte`의 `popupAnchor(rect)`가 기존에
`rect.top > 96`(선택 영역이 화면 위쪽에 너무 붙어있지 않으면) 기준으로
팝업을 **선택 영역 위**에 띄우고 있었다. 사파리 콜아웃도 선택 영역
위쪽에 공간이 있으면 위쪽에 뜨는 것으로 일반적으로 알려진 동작(공식
문서로 명확한 확인은 실패 — 웹서치로도 위/아래 기본 방향을 문서화한
자료 미발견, 관찰과 일반적으로 알려진 동작에 근거), 둘 다 "위"를
선호해 겹친 것으로 판단.

## 적용한 수정

`popupAnchor(rect)`의 기본 방향을 반전 — **아래쪽에 팝업을 띄울 공간이
부족할 때만 위로** 배치.

```js
const popupHeight = coarsePointer ? 160 : 120;
const above = window.innerHeight - rect.bottom < popupHeight;
```

- 아래쪽 여유 공간(`window.innerHeight - rect.bottom`)이 팝업 예상
  높이보다 작을 때만 위로 플립.
- 터치 환경(`coarsePointer`)은 팝업이 더 크므로(스와치 44px 등,
  `docs/pdf-highlight-popup.md`의 터치 타겟 확대 참고) 여유 높이
  기준을 120에서 160으로 더 크게 잡음.

## 남은 불확실성

- 사파리 콜아웃의 실제 위/아래 배치 기준을 공식 문서로 확인하지 못해,
  "보통 위를 선호한다"는 전제가 모든 iOS/Safari 버전·상황에서 항상
  맞는다는 보장은 없음.
- 아이패드 가로모드 스플릿 화면 등 특수 레이아웃에서는 콜아웃이 화면
  밖으로 나가는 사례도 보고돼 있어, 해당 수정 이후에도 특정 상황에서는
  여전히 겹칠 가능성 존재.
- 최종 판단은 사용자가 실기기에서 확인 필요.
