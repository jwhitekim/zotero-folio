# 하이라이트 팝업과 사파리 텍스트 선택 콜아웃 겹침

태블릿에서 단어를 더블탭(더블클릭)하면 사파리 네이티브 텍스트 선택
콜아웃(Copy/Look Up/Share 메뉴)이 형광펜 색상 팔레트 팝업과 겹치는
문제의 조사와 해결 방식 기록. 2차례 시도 끝에 해결.

## 검토한 방향과 배제 사유

| 방향 | 배제 사유 |
| --- | --- |
| `-webkit-touch-callout: none`으로 사파리 콜아웃 제거 | 링크/이미지 롱프레스 메뉴만 막고, 텍스트 선택 콜아웃엔 적용 안 됨(iOS 버전에 따라 아예 안 먹는 사례도 보고됨) |
| `-webkit-user-select: none`으로 선택 자체 차단 | 형광펜 기능에 필요한 네이티브 선택까지 같이 사라짐 — 채택 불가 |

## 1차 시도 — 우리 팝업 위치를 아래로 우선 (실패)

사파리 콜아웃은 그대로 두고(복사 기능 보존), 우리 색상 팔레트/삭제
확인 팝업의 기본 방향만 아래로 바꿔 겹침을 피하려 함.

**가설**: `PdfViewer.svelte`의 `popupAnchor(rect)`가 기존에
`rect.top > 96` 기준으로 팝업을 **선택 영역 위**에 띄우는 상태였음.
사파리 콜아웃도 위쪽에 공간이 있으면 위쪽에 뜨는 것으로 보고
(공식 문서 미확인, 관찰에 근거), 둘 다 "위"를 선호해 겹친다고 판단.

**적용**: `popupAnchor(rect)`의 기본 방향을 반전 — 아래쪽 공간이
부족할 때만 위로 배치.

**실기기 확인 결과**: 가설이 틀림. 우리 팝업을 아래로 내리니 **사파리
콜아웃도 따라서 아래로 이동**해 계속 겹침 — 사파리 콜아웃은 고정
방향이 아니라 그때그때 가용 공간을 계산해 배치되는 것으로 보이며,
사파리의 계산 기준이 Folio 쪽과 유사해서 어느 방향으로 바꿔도 같은 쪽으로
쫓아오는 것으로 추정. "방향을 비켜서 피하는" 전략 자체가 성립하지
않음을 실기기 테스트로 확인.

## 2차 시도 — 네이티브 선택 제거 + 복사 버튼 추가 (채택)

방향을 피하는 대신 사파리 콜아웃 자체를 없애기로 결정. 이전에
"복사 기능이 사라진다"는 이유로 배제했던 방법을 사용자가 재검토 —
Look Up/Share/Search Web 등 콜아웃의 다른 기능은 거의 안 쓰고 복사만
자주 쓴다는 판단으로, **복사 기능만 우리 팝업에 버튼으로 옮겨서
보존**하는 조건으로 채택.

**적용**(`PdfViewer.svelte`):

- 팝업에 필요한 정보(선택 텍스트 `selection.toString()`, 위치
  `range.getBoundingClientRect()`)를 다 읽은 직후,
  `window.getSelection().removeAllRanges()`로 네이티브 선택을 지움 —
  사파리 콜아웃도 함께 사라짐.
- 선택을 지우는 시점은 **pointerup 이후**(드래그 완전 종료 후)로
  한정 — `touch-gestures.js`의 팬-vs-선택 판정(pointermove 중
  `getSelection()`으로 구분)이 이미 끝난 뒤라 서로 간섭하지 않음.
- 색상 팔레트 팝업(`colorPopup`)에만 원형 복사 버튼 추가.
  `navigator.clipboard.writeText()` 우선 시도, 실패 시
  `document.execCommand('copy')` 폴백, 그마저 실패하면 기존
  `showHighlightError()`로 안내. 성공 시 아이콘이 1.5초간
  체크마크로 전환. 삭제 확인 팝업(`deletePopup`)에는 추가하지 않음.

## 남은 불확실성

- 사파리 콜아웃이 실제로 사라지는지, 클립보드에 텍스트가 정확히
  들어가는지는 개발 환경(터치스크린 없음)에서 재현 불가 — 최종 확인은
  사용자가 실기기(아이패드 사파리)에서 필요.
- 사파리가 향후 버전에서 텍스트 선택이 있을 때 콜아웃을 다른 트리거로
  다시 띄우는 식으로 동작을 바꾸면 해당 우회가 무력화될 가능성 존재.
